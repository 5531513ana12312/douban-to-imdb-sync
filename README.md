# Douban to IMDb Sync

在 Tampermonkey 中运行的豆瓣「看过」迁移脚本。将豆瓣个人评分或看过状态同步到 IMDb，支持读取全部分页、暂停、断点继续和失败重试。

> 原作者：**ryen（Anderson-Ryen）**。原项目：[Adsryen/Douban-to-IMDb](https://github.com/Adsryen/Douban-to-IMDb)。
>
> 本仓库是基于原作者项目修改的版本，由 [5531513ana12312](https://github.com/5531513ana12312) 修改与维护，重点改进速度、缺少 IMDb 编号时的搜索匹配和保存核验。保留原作者署名及 MIT 许可声明。

当前版本：`2026.10.14.5`，实验版。模拟浏览器测试通过；真实账户迁移仍建议先试一部，核对结果后再批量同步。

## 功能

- 优先使用豆瓣提供的 IMDb 编号；缺少编号时自动用原名、英文名和别名搜索 IMDb。
- 自动匹配前核对 IMDb 页面中的片名、年份，并在资料可用时核对导演及片长；不确定的候选留待人工确认。
- 在待核对区域选择候选、换名称搜索，或手动填入 IMDb 编号/链接。
- 豆瓣 1–5 星转换为 IMDb 2、4、6、8、10 分。
- 未评分的影片只标记 **Mark as watched**。
- 默认保留 IMDb 已有的不同评分；可主动选择覆盖。
- 默认最多两部并行，可选 1、2、4、6、8、10、16 部；同一 IMDb 条目不会同时写入。
- 面板显示本轮已确认数、工作页数量、用时和实际处理速度；速度包含已评分跳过与保留原评分。
- 等待本片账户资料和按钮加载；默认每开 30 个工作页休息 20 秒。账户加载失败后整批等待恢复，降到单部续传。提交前记录核验阶段，恢复时先只读核验，避免重复提交。
- 复用已读取的影片资料和搜索缓存，减少固定等待。
- 自动读取全部「看过」分页并去重。
- 支持暂停、继续、失败项重试和导出同步记录。
- 不依赖 jQuery 或第三方脚本 CDN。

## 安装

1. 在桌面浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开仓库中的 [`douban-to-imdb.user.js`](douban-to-imdb.user.js)，点击 **Raw**。如果 Tampermonkey 显示安装页面，按页面指引安装。
3. 如果没有出现安装页面，复制脚本全文，在 Tampermonkey 的「添加新脚本」中替换默认内容并保存。
4. 启用脚本，允许 Tampermonkey 访问 `movie.douban.com` 和 `www.imdb.com`。
5. Chrome/Edge 如未执行脚本，请按 [官方说明](https://www.tampermonkey.net/faq.php?q=Q209)检查 **Allow User Scripts** 或开发者模式。

升级已有版本时，**编辑原来的脚本并覆盖代码**，以保留队列；停用重复安装的版本。如果页面同时出现两个面板，应保留有历史进度的那份脚本。

新版本增加 IMDb 搜索连接权限。更新时如 Tampermonkey 提示，允许连接 `v3.sg.media-imdb.com`。查询仅发送影片名称，使用匿名请求，不发送 IMDb 登录 Cookie。

## 使用

1. 在同一个浏览器配置中登录豆瓣和 IMDb，将 IMDb 页面语言设置为 **English**。
2. 打开自己的豆瓣「看过」列表，使用网格视图：`https://movie.douban.com/people/你的ID/collect`。
3. 在右下角面板点击 **读取本页**，检查片名和评分。
4. 点击 **先试 1 部**。缺少编号时会自动搜索并核对；不确定的结果转入待核对，继续查找第一部可同步影片。队列为空时会先自动读取本页。
5. 在 IMDb 的个人评分或 **Your watch history** 中核对试同步结果。
6. 点击 **读取全部看过**，等所有分页读取完成，再点击 **同步待处理**。

同步过程中保持豆瓣控制页在前台，IMDb 工作页会在后台打开，核验完成后自动关闭。默认最多同时处理两部；可选择更高并发，16 部为实验选项。保留默认勾选的「自动稳速」，每开 30 个工作页会等待当前工作页结束并休息 20 秒。账户加载失败时停止开新页，等待当前工作页结束，再等待 30 秒并降到单部；连续恢复失败时等待时间增加至 60、120 秒，之后仍失败就保留记录并暂停。连续确认 20 部后，下一个批次最多恢复到两部。每个新工作页间隔至少 350 毫秒，豆瓣详情和搜索请求保留原间隔。实际耗时取决于网络、IMDb 页面加载和网站验证。

Chrome 会限制后台页面的计时器；将整个浏览器最小化或长期把豆瓣控制页放在后台，可能明显变慢。参见 [Chrome 官方计时器说明](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)。这些选项表示同时处理的上限，不保证实际一直占满。

当前版本的故障恢复验证见 [自动续传报告](ADAPTIVE.md)。[速度测试报告](PERFORMANCE.md) 是 2026.10.14.3 的历史测量，[恢复验证报告](RECOVERY.md) 对应 2026.10.14.4。本地模拟上限不等于 IMDb 的服务上限；30 部／20 秒是保守的起始策略，未测得实站最优速度。

「读取全部看过」从未筛选的第一页开始。如果只想同步筛选后的部分影片，使用「读取本页」并手动翻页读取。

## 同步规则

| 豆瓣记录 / IMDb 现有状态 | 处理方式 |
| --- | --- |
| 豆瓣 1、2、3、4、5 星 | IMDb 2、4、6、8、10 分 |
| 豆瓣看过，未评分 | 只标记看过 |
| IMDb 已有相同评分 | 跳过 |
| IMDb 已有不同评分 | 默认保留；勾选覆盖后才修改 |
| 豆瓣详情没有 IMDb 编号 | 搜索 IMDb，核对通过后同步；有歧义则进入待核对 |

选择 **只标记看过，不写入评分** 可以只迁移观影历史。

IMDb 的 Watchlist 是想看列表；本项目使用个人评分和看过功能。参考 [IMDb 官方看过功能说明](https://help.imdb.com/article/imdb/new-features-updates/mark-as-watched-faq/GR2SD7Y4LZVNHUVH)。

## 暂停和恢复

- **暂停**：停止开启新工作页，已开启的工作页完成后停止；尚未开启工作页的记录回到待同步。再点「同步待处理」继续。
- **失败项重试**：重新处理需处理的条目及其余待同步影片，先检查 IMDb 现有状态。
- **待核对**：展开影片，查看候选的 IMDb 页面，点击「选用此条目」后再点「同步待处理」。也可换用原名/英文名搜索，或手动保存 IMDb 链接。
- **账户加载失败**：默认等待恢复并降到单部续传；连续三次恢复仍失败后暂停。关闭「自动稳速」则保留手动恢复方式。
- **提交后界面未更新**：刷新核验保存状态。账户加载失败后续传仍只读核验，不重复点击；页面明确显示未保存时保留该条为需处理，继续其他影片。
- **登录、验证或连续恢复失败**：显示原因并暂停。完成网页提示或处理网络问题后再重试。
- **单部豆瓣详情 404/410**：保留该记录为需处理，继续其余影片。
- **导出记录**：下载本地 JSON 记录供核对；当前版本不提供导入该备份的功能。
- **清空队列**：清理本地进度，不会撤销已写入 IMDb 的记录。

本地队列保存在 Tampermonkey 的脚本存储中。恢复时使用同一浏览器配置、同一脚本。旧版本因缺少编号而失败的条目，升级后点击「失败项重试」，会进入新的搜索流程。

## 已有评分却提示提交按钮不可用

2026.10.14.2 修复了 IMDb 先显示禁用的 Rate 加载占位、再异步显示已有个人评分时的时序问题。已有相同评分会直接确认完成；不会等待 IMDb 对重复评分禁用的提交按钮。打开弹窗后和等待提交期间也会再次核对已有评分。

如果旧版本已经因此暂停，编辑原脚本更新并刷新豆瓣，再点击「失败项重试」。保留原队列即可。

## 已知限制

- 不能保证 IMDb 收录了每一部豆瓣影片。找不到或无法确认时会保留为待核对；只能对 IMDb 上实际存在的条目标记或评分。
- 搜索接口可能仅显示英文名。唯一同年候选会在影片页面再次核对原始片名，核对通过前不会改动账户。
- 同名同年作品、导演不一致、年份相差过大或资料不足的结果需要人工核对。
- 公共搜索接口及网页结构可能改变或限制访问。搜索受限时可手动填入 IMDb 链接。
- 不迁移豆瓣短评、标签或原观看日期。
- IMDb 页面语言、登录状态或页面改版可能影响操作；无法确认保存时不会报告成功。
- 电影和电视剧按豆瓣「看过」列表中的对应条目处理。
- 读取大量分页可能遇到站点验证或限流，应按面板提示暂停处理。

## 开发与验证

用户安装脚本无需 Node.js。运行测试需要 Node.js 20 或更新版本。

```sh
npm install
npx playwright install chromium
npm test
```

如需使用已安装的 Chrome，可设置 `CHROME_PATH` 为浏览器可执行文件路径。

测试使用临时浏览器配置、模拟页面和模拟 Tampermonkey 存储，拦截全部网页请求。覆盖评分换算、未评分、保留已有评分、刷新核验、分页、并行队列、暂停恢复、搜索、缓存、候选选择、同名不同年份、导演/片长冲突和日文原名等场景。测试不会操作真实账户。

运行后，结果保存为 `tests/browser-fixtures-results.json`。模拟测试不等同于在所有浏览器和真实账户中完成端到端验证。

只运行当前两种多工作页故障恢复测试：`BENCH_RECOVERY_ONLY=1 npm run benchmark`（macOS/Linux 终端），结果写入 `tests/concurrency-adaptive-results.json`。该测试缩短等待时间，验证流程和单次写入保护，不测量网站速度。

运行多标签页性能测试：`npm run benchmark`。它使用 1201 条模拟队列和真正的多个独立工作页，包含提交后刷新核验、暂停、失败和重复条目场景。24/32 并发只在测试中临时开放；分发脚本上限为 16。完整原始结果保存在 `tests/concurrency-benchmark-results.json`。

## 页面停在 Loading 或点击看过无变化

2026.10.14.5 将逐页短暂刷新改为整批等待后降速续传，减少多个失败工作页一起刷新。临时失败的工作页会关闭；已提交的任务保留核验目标，在新工作页只读核验。

升级时编辑原有脚本覆盖保存，关闭旧的失败工作页，刷新豆瓣页面，确认面板标题包含 2026.10.14.5。保留「自动稳速」勾选并先选择两部，再点击「失败项重试」。已确认的进度会保留，不要清空队列。

等待期间可以暂停，待同步记录及只读核验目标会保留；再次「同步待处理」继续。网站持续断网、登录或验证提示仍需要手动处理，脚本不会把无法确认的结果算作成功。
